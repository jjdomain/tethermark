# Community Edition Security Threat Model

This document defines the Phase 11 security boundary for a Tethermark Community Edition installation. It covers local workstation and trusted-team deployments; it does not claim hostile multi-tenant or direct-Internet isolation.

## Assets and principals

Protected assets include model/API credentials, the local Codex ChatGPT session, source repositories, audit evidence, review decisions, webhook signing secrets, runtime artifacts, and host filesystem/network access. The relevant principals are the local operator, an API-key holder, the Tethermark processes, external Git/tool publishers, webhook receivers, an audited repository, and code running inside the Local Runtime Sandbox.

An API key holder is an administrator in Community Edition. The key is not a substitute for per-user identity, and a holder can start audits, change settings, read local audit data, and invoke explicitly enabled local integration actions. External API/UI binding therefore remains behind the separate fail-closed network-exposure policy.

## Trust-boundary register

| Boundary | Primary threats | Enforced controls | Residual risk and operator duty |
| --- | --- | --- | --- |
| API/model key storage | keys returned by settings APIs, written into job records, logs, backups, or world-readable files | Model keys submitted through Settings are moved to the resolved protected environment file, removed from persisted UI settings, masked in responses, and never accepted inline in a durable async request. API authentication uses timing-safe comparison. On Unix-like systems the environment file, SQLite, and audit files/directories are forced to owner-only modes. Shared-service examples establish a dedicated identity, immutable checkout, owner-only Unix state, and explicit Windows ACL boundary. | Environment variables and process memory remain visible to sufficiently privileged local users. Windows operators must independently verify effective ACL inheritance after installation. Rotate a key after suspected exposure and protect backups as secrets. |
| Codex sign-in/session discovery | copying or logging OAuth tokens, reading an attacker-selected cache, using a session for unattended work, or executing an unexpected command | Only `CODEX_HOME/auth.json` or the current user's default Codex home is inspected. The status reader accepts only a regular, non-symlink file of at most 1 MiB, derives bounded expiry/plan metadata, and never returns token values or the auth-file path. CLI status is a bounded no-shell process. The model subprocess receives an allowlisted environment, and ChatGPT-session use is limited to explicit interactive-operator work. | The advanced Codex command is local administrator configuration and therefore carries local command authority. Tethermark does not copy, back up, repair, or delete the Codex cache. OS-level compromise defeats this boundary. |
| Logs and artifacts | secret-bearing nested objects, credentialed URLs, model prompts/responses, source excerpts, or runtime output leaking into consoles/exports | Structured logs recursively redact secret-bearing keys, common inline secret assignments, and URL user information. Provider traces record credential class/source rather than values. Artifact paths are per-run, and Unix files/directories are owner-only. Runtime stdout/stderr, health checks, and files are bounded. | Findings and evidence can legitimately contain sensitive source material. Treat `.artifacts`, SQLite, diagnostics, exports, and backups as confidential until reviewed/redacted; publication remains a human decision. |
| Webhooks | SSRF to host metadata/private services, unsigned remote callbacks, redirect pivots, leaked response bodies, or a callback authorizing state changes | Unsigned completion callbacks and unsigned generic webhooks are loopback-only. A remote generic webhook requires an HMAC secret and HTTPS. Targets reject URL credentials, query strings, fragments, private/special DNS answers by default, redirects, and calls over ten seconds. Response bodies are discarded. There are no inbound CE webhooks. | A signed private-network receiver requires the explicit `HARNESS_ALLOW_PRIVATE_WEBHOOKS=1` exception and remains administrator-controlled. DNS is checked before the request but CE is not a hardened egress proxy; use firewall/proxy policy for stronger anti-rebinding enforcement. Receivers must treat completion callbacks as advisory. |
| Tool archive extraction | checksum substitution, path traversal, absolute paths, symlink/hardlink writes, special files, decompression/resource exhaustion | Publisher assets and Python wheels are digest allowlisted. Before extraction, archive names and verbose types are bounded and checked; absolute/traversal/link entries are rejected. Download/extracted size and entry count are capped, the extracted tree is revalidated, only the expected executable is copied, its version is checked, and temporary data is removed. | The pinned Playwright implementation transports browser archives whose upstream manifest does not publish archive digests; its package/manifest revision controls are documented separately. A compromised publisher artifact can require a lock update and review. |
| Repository cloning | option injection, credential leakage in URLs/errors, unsafe protocols, interactive credential prompts, environment-secret inheritance, hooks/submodules, or executing untrusted code during static audit | Repository targets accept only HTTPS or Git SSH forms, reject embedded credentials/query/fragment/control data, use `--` before clone operands, disable terminal prompts, and give Git an allowlisted environment. Credentials must come from the local Git credential helper or SSH agent. Clones use a per-run sandbox, do not recurse submodules, and static audits never execute target code. Persisted provenance uses a credential-free public URL. | Git credential helpers and SSH host trust are operator-managed. Source files are untrusted input and may contain malicious parser payloads; keep scanners pinned and run target behavior only in the runtime sandbox. |
| Runtime mounts | mounting arbitrary host paths, source mutation, symlink escape, host-secret access, artifact overwrite, network exfiltration, or persistent containers/volumes | Target and artifact realpaths must be separate. Source is staged from a read-only bind into a size-capped named volume while copying regular files only; symlinks are skipped. Artifact scratch is separate and capped. Workloads use digest-pinned images, non-root users, read-only roots, dropped capabilities, `no-new-privileges`, bounded tmpfs/resources/output, network-none by default, and explicit allowlisted proxy phases. Cleanup is measured and persisted. | Docker Desktop uses a shared VM and remains a warning backend. Runtime engine administrators retain host-equivalent authority. A kernel/runtime escape is outside CE's application boundary; keep the certified engine current and prefer rootless Podman/gVisor where available. |

## Data flow and publication boundary

Untrusted repository and endpoint metadata enters preflight, then source is copied or cloned into a per-run workspace. Static tools and model agents consume bounded source/evidence; only the runtime provider may execute target code. Normalized records go to SQLite while larger/debug records go to `.artifacts`. Outbound webhooks and exports are explicit egress points. Nothing in an audited repository is an instruction to the Tethermark operator or a reason to weaken policy.

Secrets must not be placed in target URLs, request hints, reviewer notes, prompts, filenames, or completion callbacks. Use server environment configuration, the local Git credential helper/SSH agent, and the local Codex session for their intended credential classes.

## Verification

The deterministic boundary regression is:

```bash
npm run test:security-boundaries
```

It covers repository URL/credential rejection, durable-request key rejection, webhook loopback/signing/TLS/private-address policy, archive traversal/link rejection, and recursive log redaction. The regular regression suite additionally covers masked settings responses, signed local webhook delivery, async restart behavior, sandbox path/mount separation, runtime quotas, secret nondisclosure, and cleanup.

Review this model whenever a new credential field, outbound URL, archive format, clone protocol, artifact class, or runtime mount is introduced.
